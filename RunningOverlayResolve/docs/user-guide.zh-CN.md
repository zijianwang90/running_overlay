# Running Overlay Resolve 使用指南（当前开发版）

本指南从导入活动与视频，到校时、添加数字控件和导出，说明当前 Workflow 面板的实际流程。插件在 DaVinci Resolve 内生成实时 Fusion 叠加层；不需要运行 Running Overlay Studio，也不先导出一条带数据的透明视频。目前面板支持心率、配速、距离和运动计时四种数字控件，尚未提供模板功能或 Studio 的完整控件目录。

## 对齐原理：每段素材各算各的

FIT 记录提供活动的绝对时间。视频素材需要确认**原始文件开始录制的绝对时间**，包括时区。Resolve 则提供这段素材放在时间线的哪一帧，以及片段从原文件的哪一帧开始使用。插件在每次同步时为每个普通速度片段计算：

```text
片段第一帧的相机时间 = 原文件录制开始时间 + 源入点帧数 ÷ 原文件帧率
片段第一帧的活动时间 = 校正后的相机时间 − FIT 活动开始时间
片段内后续帧的活动时间 = 第一帧的活动时间 + 片段已播放时长
```

“校正”来自可选的相机时钟标定：一个锚点修正固定快慢，两个相隔一段时间的锚点还可修正时钟漂移。实际计算使用整数微秒和有理数帧率，避免把 29.97 fps 简化成 30 fps。

例如，原文件在 `2026-09-29T10:00:00-04:00` 开始录制，FIT 在同一瞬间开始，而时间线片段从原文件第 12 秒开始使用，那么片段显示的第一帧对应活动第 12 秒。片段放在 Resolve 时间线的 `01:00:00:00`，不会使它对应活动一小时处。下一次剪切会根据下一片段自己的原文件录制时间和源入点重新计算；空隙没有映射，叠加层透明。映射超出活动记录范围时也透明。FIT 暂停不压缩对齐时间轴，但“运动计时”控件会扣除 FIT 的暂停时长。GPX 没有 FIT 计时器事件，不能据稀疏轨迹点推断暂停。

这是一种**基于时间戳和源入点的对齐**，不是画面、音频或 GPS 轨迹的自动匹配。如果不知道某段原文件何时开始录制，当前插件不会猜测一个看似正确的时间。

## 开始前

1. 安装与当前开发版配套的 Workflow 插件和 `RunningOverlayNumeric.fuse`；更新 Fuse 后重启 Resolve。安装位置和构建方法见[子项目 README](../README.md#development)。
2. 在 Resolve 中创建或打开项目，把原始视频导入媒体池，按需要剪辑到一条明确的**参考视频轨道**上。片段之间可以有空隙和跳切。当前同步仅支持已验证的普通速度、外部视频源；变速、倒放、冻结、速度曲线、多机位、复合片段及未经验证的效果会被拒绝。
3. 准备同次活动的 FIT 文件，或带明确时区时间戳的 GPX 文件。最好同时准备每个原始视频文件的录制开始时间。若相机时钟与 FIT 设备时钟不一致，再准备一两个可以对应到同一真实瞬间的时间对。

## 从导入到叠加

### 1. 打开面板并导入活动

在 Resolve 打开目标时间线后，选择 **Workspace > Workflow Integrations > Running Overlay Resolve**。在面板的 **1. Activity** 点击 **Choose**，选择 `.fit` 或 `.gpx`。面板会显示导入后的记录数量和时长。`.json` 选项供已规范化活动数据的开发测试使用。

活动文件由插件在本机解析，FIT 的真实经过时间是对齐依据；时间线没有因为 FIT 暂停而自动跳过那段真实时间。缺失的心率、配速等值保持缺失，显示为不可用值，不会借用相邻记录伪造数据。

### 2. 指定参考视频轨道并扫描

在 **2. Reference track** 填入承载原始视频片段的轨道编号，点击 **Scan**。插件只读取选定轨道，不移动、修剪或重排源片段。扫描会核对 Resolve 中的片段、原文件帧率、源入点和一份临时的 Resolve 时间线证据；缺少原文件帧率、源映射不一致或不支持的片段会显示诊断，并阻止同步。

参考轨道应保持启用。若片段被禁用，它不会产生同步区间；若参考轨道中存在无法确认的重叠或源映射，先在 Resolve 中处理，再重新扫描。

### 3. 确认原文件录制时间

在 **3. Capture times** 查看每个原始素材的候选时间。请核实或填写**原文件第一帧的录制开始时间**，不要填剪辑后片段的入点时间、Resolve 时间线起点、文件导入时间或 FIT 开始时间，除非它们确实与原文件开录瞬间相同。时间必须带时区，例如 `2026-09-29T10:00:00-04:00` 或 `2026-09-29T14:00:00Z`；勾选 **Confirm capture start**。同一原文件在时间线出现多次，只需确认一次。

Resolve 提供的日期可能是容器创建时间，不能一概当作拍摄时间。插件仅在有足够独立证据时自动接受；单个看似合理的日期仍须人工确认。若没有可靠的录制时间，当前版本无法安全生成该片段的映射。第 4 步的相机标定用于修正时钟，不能替代此处的原文件录制时间。

### 4. 按需校正相机时钟

如果相机显示 `10:00:05`，而 FIT 设备在同一真实瞬间记录 `10:00:00`，在 **4. Camera clock calibration** 对应相机组填入一对相机时间与活动时间，插件便可修正约 5 秒的固定偏差。若一段长录像前后偏差逐渐变化，可提供两个相隔较远的对应瞬间，用于估算有界时钟漂移。每个时间仍须带时区。

没有已知偏差时可以留空。锚点是两个设备对**同一瞬间**的读数，不是时间线位置，也不是把某个视频画面随意拖到某个 FIT 点。

### 5. 选择和排列控件

在 **5. Overlay widgets** 添加或移除心率、配速、距离、运动计时；每种最多一个，总数为一至四个。使用上下箭头调整列表顺序，再选 **Vertical stack**、**Horizontal row** 或 **Two-column grid** 作为初始布局。改变选择或布局后，下一次应用会按列表位置设置控件起始位置。

目前这里尚不能选择 Studio 式模板。控件的精细位置、字号、标签、字体和颜色仍在创建后到 Fusion 中调整。

### 6. 保存设置并创建叠加层

**Save settings** 只保存面板配置，不改 Resolve 时间线。确认活动、参考轨道、录制时间和控件后，点击 **Create / Update Overlay**。插件会再次扫描并检查时间线是否在扫描后改变；若有变化，按提示重新 **Scan**。只有所有启用片段都有安全映射，才会继续。

成功后，插件在独立的视频轨道创建一个受管理的 Fusion 合成，将活动记录和逐段时间映射连接到一个 Numeric Fuse。面板显示同步区间数。将播放头放在有视频且落在活动数据范围内的帧，预览应显示数值；参考轨道空隙处应透明。插件不会修改参考视频片段。

### 7. 在 Fusion 中微调并保存项目

选中受管理的叠加片段，进入 Fusion，选择 Numeric 节点。可分别调整四种指标的位置、尺寸、标签、字体和颜色；位置输入提供 Fusion 原生位置控件。完成后保存 Resolve 项目。插件的面板设置和不可变数据包保存在本机的 **Running Overlay Resolve** 应用支持目录中；保存 Resolve 项目时请保留这些本机数据包，否则既有合成可能失去数据源。

## 剪辑修改后的更新

修改参考轨道的剪切、源入点、启用状态或长度后，回到面板点击 **Scan**，核对录制时间，再点 **Create / Update Overlay**。插件按当前时间线重新生成映射。普通更新沿用已有 Fusion 控件的样式和动画；如果参考范围变了，插件会替换自己的受管理叠加片段并导入原 Fusion 合成。不要通过复制受管理片段来建立第二个同所有权的叠加层；重复所有权会阻止更新。

面板打开时会定期检查是否需要更新，但**不会自动改写时间线**。Resolve 正在渲染时，扫描暂停，创建和更新也会被拒绝；渲染结束后再操作。更改叠加片段长度时，单独加在 Edit 页片段上的效果目前不能保证随替换保留。

## 导出

- **普通成片**：在原时间线中保留视频与上方的实时叠加层，按项目常规方式在 Deliver 导出，得到视频与数据合成画面。
- **仅导出透明叠加层**：复制时间线，只在副本中保留受管理叠加层，然后导出 QuickTime ProRes 4444，启用 **Export Alpha**，选择 **Straight** alpha。当前已在 1080p30 合成的独立导出中验证可见数字及空隙透明；四指标完整 Deliver、UHD 和色彩管理仍需进一步验证。不要通过仅关闭原时间线的视频轨道来推断透明导出是否正确。

本地配置和数据包尚未形成可直接跨电脑迁移的便携项目。跨机器交付、签名安装、更多相机元数据与完整控件目录属于后续开发范围。具体宿主验证范围见[测试记录](testing.md)。
