# Project Log — October 2026

## 2026-10-26

### Arrow-Key Overlay Nudging

- With an unlocked overlay selected, all four arrow keys now move it by one
  output pixel at the project resolution, or ten with Shift. Previously only
  Up/Down moved overlays, by a coarse 1% of canvas height, and Left/Right
  always stepped the playhead, so overlays could not be nudged horizontally.
- Without a movable overlay selection, Left/Right still step one project
  frame; Up/Down are passed through.
- Checked whether single-key menu shortcuts (Space, K, L, Shift+Z) swallow
  typing in text fields: a synthetic-event probe on macOS 27 showed the
  focused field receives the characters and the menu items do not fire, so
  no change was made there.
- Verification: new `EditorArrowKeyTests`; `./scripts/check.sh`.

### Inspector Dead-Code Cleanup

- Removed unreferenced and unreachable code from `ParameterPanelView.swift`
  (1660 → ~830 lines): `ClipInspectorView`, `InspectorPanel`, the unused
  `InspectorTileButtonStyle` / `InspectorRowButtonStyle`, the legacy
  `OverlayDetailView` / `OverlayDetailHeader`, and the private row controls
  only that view used (`InspectorSegmentedPicker`, `InspectorReadOnlyRow`,
  `InspectorTextRow`, `InspectorNumberRow`, `InspectorPickerRow`,
  `InspectorSliderRow`, `ColorSwatchRow`, `ColorSwatchButton`), plus the
  private extensions and `InspectorTheme` tokens that became unused.
- Every `OverlayElementType` already routed to a dedicated detail view, so the
  legacy view was only reachable as the fallback for a missing overlay. That
  fallback is now the small `MissingOverlayInspectorView`, which renders the
  same `Inspector` header with a `Missing` status and an empty body; no
  user-visible behavior changes for existing overlay types.
- Updated `docs/development/overlays-and-preview.md` and
  `docs/design/panels/inspector/inspector-ui.md` to stop pointing at
  `OverlayDetailView`.
- Verification: `./scripts/check.sh`.

## 2026-10-17

### BT.709 Color Tags On Overlay Export

- HEVC-with-alpha and ProRes 4444 exports now tag BT.709 color primaries,
  transfer function, and YCbCr matrix. Previously the MOV had no color tags,
  and DaVinci Resolve lifted the background by roughly 16/255 everywhere the
  overlay clip covered the frame, even where alpha was 0. The exported pixels
  were already correct: transparent areas decode to Y=16, Cb=Cr=128 with alpha
  0.
- Decoded pixels are bit-identical before and after the change for both
  codecs; only the stream metadata differs.
- Verification: new `exportTagsBT709ColorAndKeepsEmptyPixelsTransparent` test
  for both codecs, which fails without the fix;
  `./scripts/test.sh ExportPerformanceTests`; `./scripts/check.sh`;
  `ffprobe` and decoded-frame hash comparison against the previous build.

## 2026-10-16

### Encoder-Bound Overlay Export

- Export now re-appends the previous pixel buffer for video frames that repeat
  the previous Layer Data sample, on every render path, instead of drawing
  the cached render again.
- Full-frame renders are converted once with vImage from the 16-bit float
  extended-sRGB `ImageRenderer` output into the 8-bit BGRA pixel-buffer
  format. CoreGraphics previously spent 25-57 ms converting each new
  full-frame image on its first draw.
- The writer wait moved from before rendering to just before append, with
  0.1 ms polling, and the HEVC `canApply` compatibility check no longer runs
  for ProRes 4444.
- Rejected rendering SwiftUI directly into the pixel-buffer context because it
  was slower and visibly changed shadows and glows, and rejected vImage
  conversion of per-overlay images because reading their lazily produced
  pixels costs more than drawing them.
- Release benchmarks on Apple M3 (1080p, 10 x 5-second clips): every
  HEVC-with-alpha configuration went from 15.1-15.8 s on `main` to
  10.2-10.6 s, within 3% of the measured 10.34 s encoder floor. ProRes 4444
  real-FIT Race went from 11.87 s to 7.79 s. Decoded ProRes output matched
  the previous build bit for bit or within 64.7 dB color PSNR with identical
  alpha.
- Verification: `./scripts/test.sh ExportPerformanceTests` with new converter
  and per-render-path frame reuse tests; `./scripts/check.sh`;
  `./scripts/visual-test.sh`; release benchmark matrix against `main` and the
  HEVC speed build; decoded-frame parity comparison.

## 2026-10-12

### HEVC Encoding Speed Priority

- HEVC-with-alpha export now sets VideoToolbox
  `PrioritizeEncodingSpeedOverQuality` and keeps the project bitrate, falling
  back to the previous settings when the writer rejects the property.
- Release benchmarks on Apple M3 reduced 1080p totals from about 15.5 s to
  10.2-12.9 s across the Interval Workout and Race templates. Alpha PSNR
  against a ProRes 4444 reference dropped from 56.1 dB to 52.5 dB, color PSNR
  from 45.2 dB to 45.0 dB, and output size grew about 32%.
- Recorded the full encoder parameter comparison, including the rejected
  variable-frame-rate experiment, in `docs/export-performance.md`.
- Verification: `./scripts/test.sh ExportPerformanceTests`;
  `./scripts/check.sh`; release template-segments benchmarks and decoded-frame
  PSNR comparison.

## 2026-10-11

### Release-Build Export Profiling

- Headless benchmark commands now write export profiles in release builds, and
  profiles record `buildConfiguration`. Profiling schema is v6.
- Added `--profile-render-model` to `--benchmark-export` and
  `--benchmark-template-segments`. It times `OverlayRenderModel` layout
  evaluation separately before each unique render and records
  `renderModelDuration` per task, segment, and overlay.
- Fixed headless benchmarks that never exited when launched without a
  terminal: `NSApp.stop` now posts a wake event so the AppKit run loop
  returns.
- A release-build benchmark round showed that debug profiles overstated model
  cost about 90x, that HEVC-with-alpha 1080p export is bound by the hardware
  encoder (about 100 fps, unchanged by 2- or 4-process parallelism), and that
  ProRes 4444 full-frame exports spend most of their time redrawing reused
  frames. Details are in `docs/export-performance.md`.
- Verification: `./scripts/test.sh ExportPerformanceTests`;
  `./scripts/check.sh`; release and debug template-segments benchmark matrix.

### Keep editor panes inside compact windows

- Fixed startup clipping caused by the preferred three-pane widths exceeding
  the 1300 pt minimum window width.
- Resolve side-pane widths from the available content width, preserve the
  Preview minimum, and bound divider drags by the remaining space. Retain
  preferred widths across window resizing and align the pool toolbar with
  the visible pane width.
- Explicitly enforce the scene content minimum size.
- Added regression coverage for minimum-width startup, enlarged side panes,
  divider limits, and restoring preferred widths on expansion.
- Validation: `./scripts/check.sh`, `./scripts/test.sh EditorPaneLayoutTests`,
  and `./scripts/visual-test.sh` passed. Built and visually checked the actual
  minimum-width app window in Media Pool and Overlay Pool modes. No visual
  snapshots changed.
