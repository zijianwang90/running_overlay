### Resolve numeric size and anchor parity

- A 1080p comparison against the Mac reference showed numeric values about three
  times too large, the clock and elapsed rows clipped at the right frame edge,
  and the weather card overlapping the elapsed row.
- Cause: the Fuse defaulted to a 0.065 value size (28 pt is the Mac default) and
  never seeded template type sizes, and it placed the value's baseline at
  `Position` while the Mac places the element's top-left corner there.
- Numeric elements now anchor top-left with the minimal preset's 10×6 padding,
  the Fuse defaults are the Mac's 28/20/16 pt value/unit/label sizes, and new
  template instances seed value/unit/label/icon sizes (design points × element
  scale over the 1280-point reference).
- Host-checked on the independent validation project at 1080p with a fresh Race
  overlay and a duplicate-pace probe slot: values, units and icons render at the
  Mac scale, the clock/elapsed rows stay inside the frame, the weather card no
  longer overlaps, and the probe received the seeded sizes while existing slots
  kept their values through save/reload. The original project was restored.
