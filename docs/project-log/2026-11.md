# Project Log — November 2026

## 2026-11-02

### Shared Skia GPU Overlay Renderer

- Replaced the preview-only SwiftUI path with one shared
  `SkiaEasyRunRenderer` for preview, export, and the editor helper. The
  renderer draws every supported overlay type in `layout.elements` order and
  uses Ganesh Metal for preview/export and the CPU raster bridge for tests.
- Ported the remaining overlay modules to Skia: numeric and decor text, route
  map, weather widget, distance timeline, running gauge, elevation chart,
  interval timeline, interval countdown, interval HUD bar, interval work
  summary, and zone edge bar. Each port ships with golden-frame tests against
  `SwiftUIOverlayVideoExporter.renderFrameCGImage`.
- Removed the SwiftUI preview fallback. In Debug builds, preview can render
  every overlay through the shared renderer via `RUNNING_OVERLAY_RENDERER=skia`
  or the preview header toggle, using a display link, paused scrubbing,
  backing-scale-aware resize, and an asynchronous MapKit snapshot preload
  outside the frame loop. SwiftUI remains the default until parity review.
- Added host preload contracts: layout, activity, canvas size, or available map
  snapshots change triggers preload; the one-time auto-preload in `draw` is
  only a safety net. Route and weather preload passes evict stale asset
  generations per family.
- Bounded per-frame caches: chart image cache LRU, icon and decor-text caches
  by count and bytes, and interval feather-mask cache by count and bytes.
  Animated SVG media slots now sample at 12 fps and pre-rasterize a finite
  frame grid instead of running AppKit image drawing per displayed frame.
- Preserved layout z-order in the SwiftUI export plan by batching only
  contiguous runs of numeric overlays.
- Recorded measured GPU throughput in ADR 0010: 1080p ProRes ~1.9x faster than
  SwiftUI export, 4K ProRes ~1.19x, 1080p preview ~119 fps, and 4K preview
  ~118 fps. HEVC alpha remains encoder-bound.
- Recorded the frozen bridge contract in
  `docs/superpowers/plans/notes/2026-11-02-skia-bridge-freeze.md` and module
  inventory notes for text, charts, intervals, and route. The Skia prebuilt is
  a development dependency only (`SKIA_DIR`); shipping it still requires the
  license/provenance entry called out in ADR 0010.
- Serialized Skia raster/Metal suites behind a process-wide test gate. Full
  runs had crashed intermittently in Skia's raster blur when several suites
  rendered concurrently, and AV export and shared UserDefaults fixtures raced
  across suites. The gate is test-only; production rendering is unchanged.
- Unified the preview map snapshot path. SwiftUI and Skia now resolve a
  `MapSnapshotRequest` through one main-actor LRU cache, so the debug renderer
  comparison shows the same MapKit image instead of two independently fetched
  snapshots with different labels and anti-aliasing.
- Added Route Map `Map Zoom` and `Map POIs` controls. Zoom maps to MapKit
  region padding; the POI toggle maps to `MKPointOfInterestFilter`. MapKit
  still has no street-label density API. Both values are part of the snapshot
  request key.
- Added Zone Edge Bar `Arrow Size` and `Threshold Size` multipliers. The
  SwiftUI view, Skia renderer, marker padding, legacy CG renderer, and
  inspector all consume the same Codable fields; older templates decode to
  `1x`.
- Known limitations: pixel-level anti-aliasing and shadow shading differ from
  SwiftUI; goldens use changed-pixel and mean-delta thresholds rather than
  byte equality. The SwiftUI export layer still ignores `element.opacity`
  (pre-existing, unrelated to this migration). Ganesh is the only available
  Skia GPU backend; Graphite is deferred.
- Verification: `SKIA_DIR=... SKIA_GPU=1 ./scripts/check.sh` passed with 474
  tests in 55 suites. A gated re-run also passed.

## 2026-11-03

### Opt-in Skia Production Export

- Recorded maintainer confirmation that prior computer-use and human preview
  acceptance basically passed; proceeded with export integration.
- Connected the existing export coordinator and PNG diagnostics to
  `RUNNING_OVERLAY_RENDERER=skia`, retaining SwiftUI as the default and fixed
  golden oracle. The preview header toggle remains preview-only.
- Added an export-owned, serialized Metal renderer that preloads assets once,
  draws into IOSurface-backed writer buffers, and completes GPU work before
  append. Reused existing sampling, segment/frame reuse, progress, cancellation,
  codec settings, and security-scoped destination access. Skia profiles identify
  `skiaMetal`; SwiftUI static/per-overlay caches are bypassed.
- Rounded frame presentation times explicitly on the existing 600-timescale
  clock to avoid floating-point one-tick truncation in short clips. Added writer
  failure checks and cancellation cleanup for every unfinished writer session.
- Added real MOV decode regression coverage for both codecs and PNG selection,
  including alpha, orientation, z-order, time sampling, reuse, and cancellation.
- Default cutover, production performance approval, and pinned binary
  distribution/signing/license work remain pending. The first production host
  uses one synchronous context; spike ping-pong throughput is not guaranteed.
- Validation: Skia GPU `./scripts/check.sh` passed (477 tests in 56 suites),
  the Skia-enabled visual regression command passed, and the default build's
  `./scripts/check.sh` passed. Headless Easy Run exports completed through the
  production entry point for both codecs, each with 90 output frames and 15
  unique samples reported as `skiaMetal`. Generated review media remains
  outside the repository.
- Human export review: the maintainer accepted both ProRes 4444 and HEVC alpha
  samples. ProRes text was visibly much clearer in this comparison. This is a
  sample-specific visual observation, not a quantified quality benchmark;
  broader performance approval and packaging remain pending.

### Source-Built m159 Ganesh / Graphite Metal Experiment

- Built Skia m159 directly from official commit
  `1bbd9b972a4667a98fb16b8441444b2282fed0ac`, enabling both Ganesh and Graphite
  Metal. Added a pinned GN/Ninja build-and-package recipe with tool checksums,
  SDK/binary provenance, Skia/skcms BSD notices and an external SDK archive.
  No binary or generated media was added to the repository.
- Added opt-in Graphite context creation, surface wrapping, recording
  insertion/submission and CPU readback behind the existing C bridge. Runtime
  selection uses `RUNNING_OVERLAY_SKIA_BACKEND`; Ganesh remains the default.
  Builds without `SKIA_GRAPHITE=1` reject Graphite instead of substituting it.
- Fixed missing Graphite raster assets with a per-recorder image upload LRU
  bounded by count and estimated bytes. Propagated upload/submission failures
  to export and avoided presenting failed preview frames. Added explicit
  backend availability and successive-frame parity regression coverage.
- Existing GPU parity limits were unchanged. The 14 focused backend, GPU
  parity and production export tests passed with the dual-backend SDK and
  Graphite selected, including map snapshot upload and both codec decodes.
- Added a serial Release comparison of m152 Ganesh, m159 Ganesh and m159
  Graphite: synthetic Easy Run, 1080p/4K, both codecs, five five-second clips,
  three rotated trials per case (36 measurements). Total-export medians
  differed by at most about 1.2%, with overlapping trial ranges; this did not
  establish a stable speedup. Graphite render-plus-sync time was slightly
  higher, and HEVC remained encoder-bound. Retained m152 as the baseline.
- Recorded the method, all raw trials, hashes, results and limitations in
  `docs/benchmarks/2026-11-03-skia-engines.md` and its JSON companion. The SDK
  guide documents rebuild, selection and verification commands. Packaging into
  the app, signing, oldest-OS support and human review of the new SDK/backend
  remain separate adoption gates. Export scheduling is a more useful next
  performance experiment than switching engine solely on this evidence.
- During baseline validation, display sleep suppressed the native display-link
  fixture (zero frames) while offscreen/explicit drawable tests passed. The
  unchanged 16-test preview suite passed with a temporary active-display
  assertion. Documented `caffeinate -d -u` for long local native-preview checks;
  no fixture assertions or production rendering behavior were changed for this.
- Final validation: m159 Graphite `./scripts/check.sh` passed with 479 tests
  in 57 suites; m152 Ganesh passed the same full check with the display kept
  active; the no-Skia default check passed with 364 tests in 37 suites. The
  m159 Ganesh focused 14-test matrix, visual regression command, Markdown links,
  publication audit and Python syntax checks passed. The SDK archive was built,
  used as the app's actual dependency, and checked for unsafe archive paths.

## Skia Product Cutover And Bounded Pipeline Experiment

- Maintainer accepted the Graphite sample and authorized sufficient-speed-first
  progress toward Skia as the sole product overlay engine. ADR 0011 records
  that decision and supersedes the earlier Ganesh/SwiftUI defaults.
- Tested one-sample render prefetch against the serial Graphite export host in
  24 rotated, fresh-process Release trials with the fixed synthetic Easy Run
  suite. It helped 1080p ProRes but gave no consistent benefit for 4K/HEVC;
  removed the implementation and temporary benchmark mode. Serial throughput
  already exceeds real time in all measured cases. No dual-context follow-up.
- Skia-enabled Debug/Release now default to Skia; dual-backend SDKs default to
  Graphite. Release preview includes the native Metal canvas and ignores the
  SwiftUI renderer override. Editor chrome and interaction remain SwiftUI;
  legacy overlay rendering remains a Debug/test oracle during acceptance.
- SwiftPM app packaging embeds/signs the Skia dylib, replaces the absolute SDK
  rpath with the bundle Frameworks path, and validates dependency paths,
  architectures and legal notices. No SDK binary is committed.
- Expanded real codec decode coverage to later activity samples and made legacy
  SwiftUI cache/benchmark tests explicitly select their comparison backend.
- Native Xcode/CI SDK integration, oldest-supported macOS, full-template app
  interaction review, Developer ID/notarization and store validation remain
  release gates. No release or submission was performed.
- Full Graphite regression exposed a feather-mask cache lifetime bug: the
  cache returned a raw image pointer that could outlive its owning `NSCache`
  entry. The draw now retains the handle through the bridge call; a deterministic
  eviction test checks valid alpha after cache removal and releases ownership
  after the draw. The isolated text golden suite also reproduced no threshold
  regressions; final full-suite rerun follows below.
- Final validation passed: m159 Graphite `./scripts/check.sh` (481 tests in
  57 suites), SDK-free full check (364 tests in 37 suites), visual regression,
  Markdown links, publication audit, Python syntax and shell syntax checks.
- Local Release bundle passes resource/dependency and deep/strict codesign
  verification. Removed both SDK and Xcode toolchain development rpaths,
  preserving the system Swift runtime and bundle-relative lookup.
- Actual sandboxed bundle smoke export passed using a staged app copy with
  synthetic inputs in Resources and output in its own temporary container.
  The original bundle remains free of test fixtures. Ad-hoc local signing
  omits Hardened Runtime to accommodate missing Team IDs; real certificate
  signing retains it and still requires distribution validation.


## 2026-11-04 — Native Skia Archive And CI Integration

- Continued the existing Skia worktree after maintainer acceptance of the local
  product bundle. Added the C++20/Objective-C++ bridge and explicit Clang module
  to the deterministic Xcode project generator. Native builds select Graphite
  by default and accept the SDK location as a build setting, with explicit
  `SKIA_ENABLED=NO` for SDK-free editor development.
- Native archives embed/sign the Skia dylib before final app signing. Both
  packaging paths check the pinned source, recipe/builder and binary hashes and
  include the exact Skia/skcms notices. Added synthetic validator regression
  tests to the standard check command; no SDK binaries or new media fixtures
  are committed.
- Added shared source-build/cache setup for CI and release workflows. The new
  Skia product job runs full Graphite checks, visual regression, ad-hoc signed native
  archiving, all built-in template smoke exports and SwiftPM packaging. The
  independent SDK-free job remains. Cache keys include the Xcode toolchain.
- Added a reusable archive smoke harness. It signs a disposable app copy with
  the sandbox on and a narrow temporary output-directory exception so the
  headless harness can check nonempty MOVs and clean them without macOS
  container privacy blocking inspection. Original app and product entitlements
  remain untouched. All three built-in templates passed native-archive smoke
  exports; this is not full-workout interactive visual acceptance.
- Local native Skia Release build and unsigned Archive passed, including
  packaged Mach-O dependency/architecture/license checks. SDK-free native Debug
  build passed. Remote GitHub Actions, oldest-OS and real-certificate signing,
  notarization and store acceptance remain unverified release gates.
- Final validation passed: standard Graphite check (481 Swift tests in 57
  suites plus four SDK-validator tests), visual regression, native SDK-free
  Debug build, unsigned and ad-hoc signed native Release archives, deep/strict
  signature verification, all three preset exports from the signed archive,
  SwiftPM Skia bundle packaging, Markdown links, publication audit, App Store
  configuration syntax, Python/shell/Ruby syntax and workflow YAML parsing.
  Standard project-regeneration comparison used a temporary Git index holding

  staging area. Fixed macOS Bash 3 empty-array handling in the ad-hoc embed
  signing branch; CI's native archive now exercises that signed path.
