### Declarative Overlay Component Persistence And Skia Path

- Added the `component` overlay element kind and project schema version 2.
  `OverlayTemplateElement` now stores `component` (id, version, digest,
  source, embedded definition) and `params`; native elements encode no new
  keys, and version 1 projects still decode unchanged.
- Component digests are now SHA-256 over canonical JSON (sorted keys, no
  insignificant whitespace) rather than raw file bytes, so embedding and
  reformatting preserve identity. `OverlayComponentRegistry` parses and caches
  definitions by digest.
- `ProjectDocument.addComponentElement(_:parameters:position:scale:)` adds an
  instance behind one undo point with the existing selection and snapshot
  flow.
- Added `OverlayComponentSkiaRenderer`, dispatched by `SkiaEasyRunRenderer`
  before the native text/interval paths. It maps design units with
  `element.scale × canvasScale`, clips to the component rect, and draws base
  and capability nodes through the existing `skb_*` primitives. Preview
  geometry and selection use the same frame.
- Not yet implemented: Inspector generation, Overlay Pool entry,
  `.rocomponent` import, bundled (`studio.*`) definitions, image assets, and
  pixel-parity approval against a native module. No UI creates a component
  element yet.
- Verification: `./scripts/check.sh` passed (415 tests in 43 suites, including
  Xcode project regeneration and Markdown links); the Skia-enabled suite
  passed (537 tests in 64 suites), including project round-trip, legacy
  decoding, undo, parameter typing, digest-mismatch handling, a Skia pixel
  probe and a `repeat`-based component render.
- Human review required for project-file compatibility (schema version 2) and
  for the eventual visual parity evidence.

### Shared Skia GPU Overlay Renderer

- Replaced the preview-only SwiftUI path with one shared
  `SkiaEasyRunRenderer` for preview, export, and the editor helper. The
  renderer draws every supported overlay type in `layout.elements` order and
  uses Ganesh Metal for preview/export and the CPU raster bridge for tests.
- Ported the remaining overlay modules to Skia: numeric and decor text, route
  map, weather widget, distance timeline, running gauge, elevation chart,
  interval timeline, interval countdown, interval HUD bar, interval work
  summary, and zone edge bar. Each port ships with golden-frame tests against
  `SwiftUIOverlayVideoExporter.renderFrameCGImage`.
- Removed the SwiftUI preview fallback. In Debug builds, preview can render
  every overlay through the shared renderer via `RUNNING_OVERLAY_RENDERER=skia`
  or the preview header toggle, using a display link, paused scrubbing,
  backing-scale-aware resize, and an asynchronous MapKit snapshot preload
  outside the frame loop. SwiftUI remains the default until parity review.
- Added host preload contracts: layout, activity, canvas size, or available map
  snapshots change triggers preload; the one-time auto-preload in `draw` is
  only a safety net. Route and weather preload passes evict stale asset
  generations per family.
- Bounded per-frame caches: chart image cache LRU, icon and decor-text caches
  by count and bytes, and interval feather-mask cache by count and bytes.
  Animated SVG media slots now sample at 12 fps and pre-rasterize a finite
  frame grid instead of running AppKit image drawing per displayed frame.
- Preserved layout z-order in the SwiftUI export plan by batching only
  contiguous runs of numeric overlays.
- Recorded measured GPU throughput in ADR 0010: 1080p ProRes ~1.9x faster than
  SwiftUI export, 4K ProRes ~1.19x, 1080p preview ~119 fps, and 4K preview
  ~118 fps. HEVC alpha remains encoder-bound.
- Recorded the frozen bridge contract in
  `docs/superpowers/plans/notes/2026-11-02-skia-bridge-freeze.md` and module
  inventory notes for text, charts, intervals, and route. The Skia prebuilt is
  a development dependency only (`SKIA_DIR`); shipping it still requires the
  license/provenance entry called out in ADR 0010.
- Serialized Skia raster/Metal suites behind a process-wide test gate. Full
  runs had crashed intermittently in Skia's raster blur when several suites
  rendered concurrently, and AV export and shared UserDefaults fixtures raced
  across suites. The gate is test-only; production rendering is unchanged.
- Unified the preview map snapshot path. SwiftUI and Skia now resolve a
  `MapSnapshotRequest` through one main-actor LRU cache, so the debug renderer
  comparison shows the same MapKit image instead of two independently fetched
  snapshots with different labels and anti-aliasing.
- Added Route Map `Map Zoom` and `Map POIs` controls. Zoom maps to MapKit
  region padding; the POI toggle maps to `MKPointOfInterestFilter`. MapKit
  still has no street-label density API. Both values are part of the snapshot
  request key.
- Added Zone Edge Bar `Arrow Size` and `Threshold Size` multipliers. The
  SwiftUI view, Skia renderer, marker padding, legacy CG renderer, and
  inspector all consume the same Codable fields; older templates decode to
  `1x`.
- Known limitations: pixel-level anti-aliasing and shadow shading differ from
  SwiftUI; goldens use changed-pixel and mean-delta thresholds rather than
  byte equality. The SwiftUI export layer still ignores `element.opacity`
  (pre-existing, unrelated to this migration). Ganesh is the only available
  Skia GPU backend; Graphite is deferred.

## 2026-11-04 — Toolbar Group Spacing And Native Title Bar Double-Click

- Widened the gap between the toolbar's Pools toggle and the segmented pool
  switch. A fixed `ToolbarSpacer` placed in the leading navigation cluster is
  compiled but collapses to zero width (confirmed by reading the live
  `NSToolbarItemViewer` frames through lldb), so the gap comes from 16 pt of
  leading padding on the pool switch item instead. Both leading and trailing
  group gaps now measure 16 pt, matching the trailing `Export` /
  Inspector spacing.
- Root cause for the missing title bar zoom: `.toolbarBackground(...,
  for: .windowToolbar)` makes SwiftUI host its own toolbar background and set
  `titlebarAppearsTransparent`, so AppKit skips its native title bar
  double-click action. An in-process event harness confirmed that dragging
  worked while double-click did nothing, and that the system action returned
  whenever the title bar was opaque. `titlebarHandlesDoubleClickWhenTransparent`
  alone did not restore it.
- Added `EditorTitlebarDoubleClickGuard`, which performs the System Settings
  title bar double-click action (`AppleActionOnDoubleClick`, with the legacy
  `AppleMiniaturizeOnDoubleClick` fallback) for the editor window. It acts only
  on the second click inside the title bar strip and ignores control clicks, so
  toolbar buttons, the pool switch, and dragging are untouched. The toolbar
  keeps its `app.chrome` background; removing the custom background instead
  would restore native handling but change the bar to the system material.
- Validation: focused `EditorTitlebarDoubleClickTests`; an in-process synthetic
  harness on the built app (blank-bar double-click zooms, control double-click
  and single click do not); and the full Graphite `./scripts/check.sh` and
  `./scripts/visual-test.sh` runs. Drag verification remains manual because
  the desktop host's coordinate automation cannot move windows; the handler
  never consumes single clicks.

## 2026-11-06 — One-Dimensional Stack Layout For Components

- Added the `stack` node: children lay out in order along `horizontal` or
  `vertical`, with `spacing`, `crossAlign` (`start`, `center`, `end`) and an
  optional container `frame`. Text nodes may now omit `frame` and are sized
  from their measured lines, so a unit can follow a value whose width changes.
- Stack children must carry a frame unless they are text or another stack;
  `circle`, `line`, `polyline` and `path` need a framing group. Loader, schema,
  resolver and renderer enforce the rule.
- Stack layout runs at draw time in pixel space. Measuring at design size and
  scaling drifts from CoreText advances as the element scales (about one pixel
  at 1.5× and three pixels at 2×), so text measurement happens at the final
  font size.
- The heart-rate parity pilot now uses a horizontal stack with auto-sized value
  and trailing unit, matching the native numeric module exactly at element
  scale 1 and 1.5, including the default element shadow. This removes the
  earlier absolute-frame workaround.
- Updated spec v0.1, the JSON schema, the ADR scope notes, the overlay
  development guide and the README milestone table.
- Fixed node-level opacity bounds for auto-sized text: the layer now measures
  the text instead of using its zero frame, which previously clipped the whole
  node. A regression test renders a half-opaque auto-sized text.
- Validation: `OverlayComponent` suites (86 tests, 7 suites) pass with Skia
  enabled; parity is exact at both scales. The full check ran 619 tests in 71
  suites; the only failure was the environment-dependent
  `displayLinkDrivesFramesInAWindow` test, which needs an on-screen window.
