## 2026-11-04

### Editor Package Clips Stay Inside Their Parents

- DaVinci Resolve truncated CAM B in a two-camera import: the connected clip
  ran past the end of the spine clip it was attached to. Final Cut Pro keeps
  such overflow, Resolve does not.
- The FCPXML layout now splits the timeline into frame-aligned segments. Each
  segment belongs to the highest-priority covering clip (lowest track index,
  then earliest start); other covering clips are connected inside it. A clip
  crossing a boundary is emitted as trimmed pieces with the matching media
  `start`, so pieces play continuously and no connected clip overflows.
- One overlay now covers each time region, so overlapping angles no longer
  attach duplicate overlays that composite twice.
- In Full Activity layout an empty stretch is filled by the overlay movie in
  the spine, keeping the data layer continuous across gaps.
- Validation: 21 editor-package tests, including the long-connected-clip and
  gap-overlay regressions; FCPXML 1.10 DTD validation; full
  `./scripts/check.sh`.
- Manual import of the fixed package into Final Cut Pro and DaVinci Resolve
  still needs verification.

### Editor Packages Pack Clips Unless Positions Are Kept

- Editor packages no longer reproduce the project timeline's empty stretches
  by default. Clips import back to back, matching how most edits are cut; an
  empty stretch only becomes a `gap` when the new "Keep original positions"
  switch is on.
- The Full Activity layout forces positions on: its single overlay lives in
  activity time, so removing stretches would move clips away from their data.
- `EditorPackageExportOptions` stores the choice (default off) and
  `EditorImportGuide` explains it in the post-export notes.
- `TimelineLayout` compacts uncovered stretches before spine and lane packing,
  so overlapping multi-track clips keep their relative offsets.
- Validation: focused editor-package and guide tests, plus full
  `./scripts/check.sh`.

### Separate Export Progress From The Export Button

- The toolbar progress control and the primary `Export` button were packed

  `ToolbarItem`s with the fixed toolbar spacer between them, matching the gap

- Validation: `./scripts/check.sh`; manual visual check of the toolbar while

### Multi-Track Timelines In Editor Packages

- Export for Editor now preserves overlapping app tracks. Clips enter the
  spine while they do not overlap what precedes them; overlapping clips from
  other tracks become connected clips on lanes above the spine item that
  contains their start. Lane packing uses frame ranges, so two camera angles
  import as V1 plus V2 and three angles as V1 plus V2 plus V3.
- Gaps appear only where no track has media, because FCPXML gaps cannot carry
  connected clips.
- A full-activity overlay shared by overlapping tracks is attached once above
  the program instead of once per angle.
- Validation: 17 editor-package tests pass, including overlapping, partial
  overlap, three-track, gap, and shared-overlay cases. Single-track and
  multi-track documents both validate against the Final Cut Pro 1.10 DTD.

  DaVinci Resolve.

## 2026-11-04 — Toolbar Group Spacing And Native Title Bar Double-Click

- Widened the gap between the toolbar's Pools toggle and the segmented pool
  switch. A fixed `ToolbarSpacer` placed in the leading navigation cluster is
  compiled but collapses to zero width (confirmed by reading the live
  `NSToolbarItemViewer` frames through lldb), so the gap comes from 16 pt of
  leading padding on the pool switch item instead. Both leading and trailing
  group gaps now measure 16 pt, matching the trailing `Export` /
  Inspector spacing.
- Root cause for the missing title bar zoom: `.toolbarBackground(...,
  for: .windowToolbar)` makes SwiftUI host its own toolbar background and set
  `titlebarAppearsTransparent`, so AppKit skips its native title bar
  double-click action. An in-process event harness confirmed that dragging
  worked while double-click did nothing, and that the system action returned
  whenever the title bar was opaque. `titlebarHandlesDoubleClickWhenTransparent`
  alone did not restore it.
- Added `EditorTitlebarDoubleClickGuard`, which performs the System Settings
  title bar double-click action (`AppleActionOnDoubleClick`, with the legacy
  `AppleMiniaturizeOnDoubleClick` fallback) for the editor window. It acts only

## 2026-11-05 — Spine Ownership Keeps Resolve Imports Intact

- After the first Resolve fix, CAM B still had a stretch without its overlay.
  Resolve misplaces connected clips whose parent spine clip has a non-zero
  media `start` (diagnostics placed the child at `-start`), while a child with
  its own non-zero `start` under an untrimmed parent imports correctly.
